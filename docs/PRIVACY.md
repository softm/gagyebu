# 개인정보·데이터 관리

## 저장 위치

- 비로그인 장부는 현재 브라우저의 IndexedDB에만 저장됩니다.
- 로그인 장부는 Firebase Authentication UID별 Firestore 경로에 저장되고, 영수증은 같은 UID의 Cloud Storage 경로에 저장됩니다.
- 서비스 계정 키, SNS Client Secret, OAuth 인가코드/액세스토큰은 정적 웹 코드·GitHub·로그에 저장하지 않습니다.
- Firestore/Storage는 종단간 암호화(E2EE)가 아닙니다. 기기 IndexedDB에도 앱 자체 암호화는 적용하지 않습니다.

## 사용자 제어

- JSON 전체 백업에는 거래·자산·분류·예산·설정과 접근 가능한 영수증이 포함됩니다. 파일 자체가 민감정보이므로 공개 공유하지 마세요.
- JSON 전체 복원과 장부 전체 초기화는 현재 장부 백업을 먼저 내려받은 뒤 두 번째 확인을 거칩니다.
- 비로그인 장부 가져오기는 추가 건수를 미리 보여주며 로그인 장부를 덮어쓰지 않습니다. 원본은 자동 삭제하지 않고 반복 실행 시 `sourceImportKey`로 중복을 건너뜁니다.
- 로그아웃 후에는 게스트 장부로 즉시 전환하고, 다른 계정 로그인 시 UID별 캐시를 따로 불러옵니다. 미전송 변경이 있으면 로그아웃 전에 경고합니다.
- 로그인 사용자는 “계정·클라우드 데이터 완전 삭제”에서 먼저 JSON 백업을 받은 뒤 확인 문구와 최근 로그인 확인을 거쳐 삭제를 요청할 수 있습니다. 서버는 해당 UID의 영수증, Firestore 하위 데이터, Firebase Authentication 계정을 순서대로 삭제합니다. Google/Apple은 재인증 팝업을 사용하고, 카카오/네이버는 로그아웃 후 다시 로그인한 다음 5분 안에 재요청해야 합니다.

## 삭제 요청과 현재 제한

앱 안의 “장부 전체 초기화”는 현재 로드된 장부의 엔터티를 tombstone 처리하고 알려진 영수증 참조를 정리합니다. “계정·클라우드 데이터 완전 삭제”는 배포된 `deleteAccountData` Functions가 최근 5분 이내 로그인 토큰을 확인한 뒤 UID 전체를 재귀 삭제합니다. 삭제 도중 일부 백엔드 작업이 실패할 수 있으므로 오류 시 같은 계정으로 다시 로그인해 재요청해야 합니다.

운영 정책으로 아직 결정해야 할 항목은 삭제 작업의 장기 상태 추적·완료 영수증, 법적 보존기간, Firebase 관리 백업의 삭제 주기입니다. 현재 앱은 자체 서버 백업을 만들지 않습니다.

운영 Firebase 프로젝트가 확정되기 전에는 다른 프로젝트의 사용자 데이터를 삭제하거나 변경하지 않습니다.
