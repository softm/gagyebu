# 한눈 서비스 공통 개발·배포 원칙 (v1.0)

> 적용일: 2026-11-13 · 대상: 한눈 서비스 중 오프라인 실행이 필요한 웹 기반 Android 앱 및 해당 웹 원본 저장소

## 1. 단일 원본과 로컬 실행
- 웹 애플리케이션의 HTML·CSS·JavaScript는 각 서비스의 **웹 GitHub 저장소(main)** 를 단일 원본으로 한다.
- 오프라인 실행이 필요한 Android 앱은 검증된 웹 리소스를 `app/src/main/assets/web/`에 포함하고 AndroidX `WebViewAssetLoader`로 로컬 실행한다.
- Android 전용 SMS·알림·OCR·광고·인증 복귀 브리지는 공통 웹 코드와 분리하고 덮어쓰지 않는다.
- GitHub Actions는 웹 원본 변경을 감지하여 Android assets로 자동 동기화하고, 원본 커밋·검증 결과를 남긴다. 웹 파일 변경은 설치된 APK에 즉시 반영되지 않으며 새 APK/AAB 배포가 필요하다.
- 동기화 실패 시 마지막으로 검증된 assets를 보존한다. 빌드 성공이 Play Store 출시 승인을 의미하지 않는다.

## 2. 온라인 인증·서버 저장·동기화
- PC 웹과 Android는 **동일한 Cloudflare 공통 계정 시스템**과 서비스별 API 계약을 사용한다. 로그인 UI·계정 식별(UID)·동기화 규칙은 공통화한다.
- Google·카카오·네이버 등 OAuth는 온라인에서 처리한다. Android는 안전한 외부 브라우저 로그인, 검증된 앱 복귀(PKCE/일회용 코드), 안전한 토큰 저장을 사용할 수 있다.
- 사용자 계정 인증, **서버에 대한 정보 저장**, 서버 데이터 조회, PC↔Android 동기화는 온라인에서만 가능하다.
- 앱의 로컬 IndexedDB/SQLite 저장은 오프라인 임시 기록·캐시일 뿐 **서버 저장 완료나 기기간 동기화로 표시하지 않는다**. 네트워크 복귀 후 명시적인 성공 응답과 충돌 처리로 확정한다.
- 서버 데이터는 서비스별 Cloudflare D1 등에 분리하고 공통 계정 데이터와 혼합하지 않는다. 예: 가계부 `gagyebu-db`.
- SMS·알림 원문 등 민감한 기기 데이터는 명시적 동의와 최소 권한 원칙을 따르며, 불필요하게 서버로 전송하지 않는다.

## 3. 안전성과 운영 검증
1. 웹 원본의 변경을 검증하고 Android 전용 코드와 충돌 여부를 확인한다.
2. 웹 리소스를 동기화하고 원본 Git SHA를 기록한다.
3. JS 문법, Android 빌드 및 네이티브 브리지의 출처 허용 목록을 검증한다.
4. 로그인, 서버 저장, PC·Android 교차 동기화, 네트워크 차단·복귀 시나리오를 테스트한다.
5. APK/AAB는 별도 출시 절차에 따라 배포한다.
6. API/DB 변경은 기존 설치 앱과의 호환성을 유지하거나 버전 업그레이드 계획을 마련한다.

## 4. 적용 범위 및 예외
| 서비스 | 웹 원본 | Android 저장소 | 적용 |
|---|---|---|---|
| 가계부 | `softm/gagyebu` | `softm/softm.android.gagyebu` | 오프라인 로컬 웹 실행 + 온라인 공통 인증/장부 API |
| 계산기 | `softm/softm.calc` | `softm/softm.android.calc` | 오프라인 웹 리소스 동기화; Android 프로젝트·서버 기능은 실제 구현 범위에 따름 |
| 기타 한눈 서비스 | 서비스별 | 서비스별 | 오프라인 실행 필요성이 확인된 경우 확대 |

> 예외: 오프라인 실행이 불필요한 서비스에는 Android assets 동기화를 강제하지 않는다. 로컬 계산 결과와 온라인 사용자 정보 저장을 혼동하지 않는다.

## 5. 운영 상태 유의
이 문서는 **공통 정책**이며, 모든 저장소에서 완전 자동화·실계정 로그인·교차 기기 동기화가 검증되었다는 뜻은 아니다. 실제 구현·테스트·배포 상태는 저장소별 GitHub Actions 및 운영 검증 기록을 따른다.
