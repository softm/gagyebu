# 가계부 Kakao AdFit 광고 계획 및 적용

작성·설정 확인: 2026-10-22 (Asia/Seoul)

- 서비스: https://softm.github.io/gagyebu/
- 저장소: https://github.com/softm/gagyebu
- AdFit 매체: 가계부 웹 / Web / `softm.github.io/gagyebu`
- AdFit 관리: https://adfit.kakao.com/adManagement/media/NDc
- 카테고리: 금융, 생산성
- 등록 시 확인 상태: **매체 심사 대기**, 광고단위 3개 생성·단위 상태 승인. 광고단위 승인과 매체 승인은 별도이며, 실제 수익 광고 송출 완료를 의미하지 않는다.

## 1. 광고 배치

| 지면 | 규격 | 노출 화면 | 목적 및 동작 |
| --- | --- | --- | --- |
| 하단 접기·펼치기 — 모바일 | 320×50 | 홈·거래 조회·달력·분석 | 가계부를 읽는 동안 1개. 메뉴와 본문 공간을 확보하며 접힘 선택을 기억 |
| 하단 접기·펼치기 — PC | 728×90 | 같은 화면, 가용 폭 728px 이상 | 모바일 단위와 상호 배타적. 사이드바 폭을 제외한 실제 공간으로 판단 |
| 분석 보고서 아래 | 320×100 | 분석 화면만 | 보고서 뒤 독립 영역. 화면에 들어올 때 최초 요청하며 최대 1개 |

한 화면의 활성 광고는 최대 2개다. 거래 금액·내역 행 사이에는 광고를 삽입하지 않는다. 첫 방문 팝업이나 전체 화면 광고는 적용하지 않는다.

## 2. 실제 발급 광고단위

| 광고단위 이름 | 단위 ID | 규격 |
| --- | --- | --- |
| 가계부_하단접힘_모바일_320x50 | `DAN-fIXGhve8Z72xQH1H` | 320×50 |
| 가계부_하단접힘_PC_728x90 | `DAN-DcWN2G6To8ZzG5Fv` | 728×90 |
| 가계부_분석보고서_320x100 | `DAN-9oJPVnQodcKlE2xz` | 320×100 |

세 광고단위는 위 가계부 매체에서 신규 생성했다. 다른 서비스의 ID를 복사하지 않았다. 관리 화면의 소재 새로고침은 60초이며, 앱 코드에는 별도 반복 요청 타이머를 두지 않는다. 접힘·입력·백그라운드에서는 광고를 정리하여 숨겨진 영역의 요청이 지속되지 않게 한다.

## 4. 사용자 동작 및 개인정보

| 상황 | 처리 |
| --- | --- |
| 광고 접기 | 소재를 정리하고 광고 바깥의 펼치기 버튼만 유지, localStorage에 선택 저장 |
| 광고 펼치기 | 현재 크기에 맞는 가계부 전용 단위 1개 요청 |
| 입력·수정·영수증·가져오기 모달 | 광고와 SDK 단위 리소스 정리, 입력 영역 확보 |
| 자산·설정·로그인·확인 필요함 | 광고 숨김 |
| 입력칸 포커스/모바일 키보드 | 광고 숨김; 입력 종료 시 저장된 사용자 선택 존중 |
| 오프라인·문서 백그라운드 | 광고 정리 |
| NO-AD·SDK 실패·단위 없음·폭 부족 | 빈 광고 공간까지 제거. 같은 세션의 실패 단위를 재렌더마다 반복 요청하지 않음 |
| 기간 변경·데이터 갱신 | 안정된 광고 DOM 유지. 전체 스캔이나 광고 iframe 재부착으로 재요청하지 않음 |

광고 모듈의 입력은 화면 종류, 필터 상태, 모달 열림 여부뿐이다. 장부 데이터, 거래 금액·메모·사용처·계좌명, 영수증, 인증정보, 사용자 UID를 광고 SDK에 전달하지 않는다. 광고 SDK 자체의 브라우저 정보·식별자 처리 안내는 `privacy.html`에 구분하여 기재한다.

## 5. 구현 구조

| 파일 | 역할 |
| --- | --- |
| `src/ad-config.js` | 실제 단위 ID, 규격, 허용 origin·경로, 활성 여부 |
| `src/ads.js` | SDK 1회 로드, 슬롯별 렌더/정리, 입력 보호, 지연 콜백 방어, 지연 로딩 |
| `src/ads.css` | 광고/메뉴/본문 공간 분리, 테마 및 반응형 처리 |
| `index.html` | 광고 스타일 및 재렌더 범위 밖의 안정된 분석 광고 호스트 |
| `src/app.js` | boot·render·모달 동작과 광고 상태 연결 |
| `sw.js` | 새 모듈 캐시 및 가계부 캐시만 갱신. 외부 광고 응답은 캐시하지 않음 |
| `tests/ads.test.mjs` | 네트워크 없이 SDK 대역으로 실제 lifecycle 위험을 검증 |

허용 주소는 `https://softm.github.io/gagyebu/`다. 다른 배포 도메인으로 옮길 때는 먼저 해당 AdFit 매체 등록 및 단위 관계를 확인하고 origin·경로 설정을 변경한다. 운영 URL에는 테스트 광고를 켜는 쿼리 옵션을 두지 않는다.

## 6. 검증

```sh
node tests/ads.test.mjs
node --test tests/*.test.mjs
node --check src/app.js
node --check src/ads.js
node --check src/ad-config.js
node --check sw.js
```

2026-10-22 로컬 검증: 광고 lifecycle 10개 통과, 기존 회계·동기화·OAuth 테스트 파일과 광고 테스트 파일 전체 통과, JavaScript 구문 검사 통과.

검증 항목: 반복 render 중 단일 요청, 접힘 저장 및 SDK 정리, 늦은 실패 콜백 무시, NO-AD 높이 0 반환, SDK 로딩 중 모달 차단, 오프라인/백그라운드/입력 보호, 분석 광고 지연 호출과 고정 DOM 유지, focusout 없이 입력 DOM이 제거된 후 복원, 단위 중복·미발급·미등록 origin 차단, SDK 실패 후 반복 스크립트 요청 방지.

운영 확인은 GitHub Pages 배포 후 PC/모바일의 요청·배치와 입력 보호 상태를 확인한다. 광고를 클릭하여 테스트하지 않는다. 심사 및 실제 소재 공급은 카카오의 처리 결과에 따른다.

## 7. 운영 확인 기준

매체 승인 후 AdFit 보고서에서 단위별 요청수·노출수·충족률·수익을 비교한다. 모바일 하단/PC 하단/분석 지면이 서로 다른 ID이므로 위치별 성과를 구분할 수 있다. 실제 트래픽을 보기 전 수익 목표를 확정하지 않는다. 입력 완료를 방해하는 겹침이 발견되면 해당 지면을 우선 조정한다.
